## 一、两个问题的直接回答

### 1.1 「拼音字母里没有 yue、ying 这种全拼吧？」

**有，而且放对了位置。**

`yue ying` 属于**整体认读音节**，不是字母。《汉语拼音方案》明文规定 16 个整体认读音节：`zhi chi shi ri zi ci si yi wu yu ye yue yuan yin yun ying`。现卡集有独立的「整体认读」子集，正好 16 张，顺序与方案一致。**这不是凑数，是教材内容。**

但有两个**命名/结构**问题值得改：

| 问题 | 事实 | 建议 |
| --- | --- | --- |
| 产品名叫「拼音字母卡」，里面却混着完整音节 | `yue ying yin yuan` 都是双/三字母音节 | 把分组名改成「字母（声母 + 韵母）」与「音节（整体认读）」，或产品名改叫「拼音认读卡」 |
| 「完整拼音表 63」把整体认读音节又排了一遍 | `完整拼音表 63 = 声母21 + y/w 2 + 韵母24 + 整体认读16`，是**复用同一批卡**，不是新的 63 张 | 保留 63 张逐张可翻是有价值的，但要明确它是「总表视图」而非新增卡片，否则用户会以为卡片重复 |

`yue / ying` 本身**不用删**。

### 1.2 「每个发音做核对」

**结论：64 个音形项目里，24 个有确定缺陷，40 个实测正确。**

你的直觉完全正确，而且比之前那版核查报告说的更严重——问题不在「汉字选得不对」，而在**技术路线本身**：`生成标准呼读音.swift` 用 `AVSpeechSynthesisIPANotationAttribute` 给 macOS 的 Tingting 语音喂 IPA，而**这个 IPA 通道是「部分且有损」的，它会静默丢掉它不认识的音素，不报错**。

## 二、逐音核对结果

### 2.1 硬错误：听感完全相同的音（字节级相同）

这些是同一段波形，孩子点 `j` 卡和点 `q` 卡，耳朵收到的**一模一样**：

| 音组 | 涉及卡片 | 性质 |
| --- | --- | --- |
| `a ≡ ai` | a、ai | **错**。ai 的双元音后段 `ɪ` 被丢弃，ai 卡听起来就是 a 卡 |
| `o ≡ ou` | o、ou | **错**。ou 的 `ʊ` 被丢弃 |
| `e ≡ er` | e、er | **错**。er 的卷舌 `ɻ` 被丢弃，er 卡没有卷舌，和 e 卡完全一样 |
| `j ≡ q` | j、q | **错**。送气标记 `ʰ` 在 `tɕ` 后被丢弃，送气/不送气对比消失 |
| `zh ≡ ch`、`ch ≡ sh` | zh、ch、sh | **错**。同上，`ʰ` 在 `ʈʂ` 后被丢弃 |
| `z ≡ c` | z、c | **错**。同上，`ʰ` 在 `ts` 后被丢弃 |

（`c≡ci`、`z≡zi`、`s≡si`、`zh≡zhi`、`ch≡chi`、`sh≡shi` 这些「相同」是**正常的**——整体认读音节的元音本来就是舌尖元音 `ɨ`，与声母呼读音同音，属拼写等价。）

### 2.2 被截断：只剩辅音，没有元音

| 音 | 时长 | 浊音比 | 症状 |
| --- | ---: | ---: | --- |
| `ao` | 0.19 s | 0.60 | 应为 `ɑʊ`，整段被砍成一个短促音 |
| `ei` | 0.19 s | 0.73 | 同上 |
| `üe`（ve / yue） | 0.19 s | 0.73 | 同上，`ɥ` 与 `ɛ` 都没了 |

### 2.3 元音被弱化：舌尖元音 `ɨ` 没读出来

`z c s zh ch sh` 以及 `zhi chi shi zi ci si` 的 IPA 都带 `ɨ`（舌尖前元音）。macOS 把 `ɨ` 渲染成了近乎清音的弱元音，分两档：

| 档 | 音 | 时长 | 浊音比 | 症状 |
| --- | --- | ---: | ---: | --- |
| 被截断 | `s sh zh ch zhi chi shi si` | 0.19 s | **0.00–0.07** | 只剩「嘶——」，几乎没有元音 |
| 弱化未截断 | `z c zi ci` | 0.28 s | **0.17** | 有元音但又扁又哑 |
| 正常参照 | 汉字自然读音 资 / 知 / 思 | 0.33–0.42 s | **0.51–0.76** | — |

也就是说，现有 z c s zh ch sh 读出来是「嘶——」而不是「资——」。**平舌音的质感丢失，正好打在这个卡集重点教的「平舌 vs 翘舌」上。**

### 2.4 多余成分：b p m f 的呼读音多了一个 u 滑动

现有 IPA 写作 `pu̯o˥ / pʰu̯o˥ / mu̯o˥ / fu̯o˥`，即在声母和 `o` 之间插了一个 `u` 滑动音。实测：**玻（bō）读出来与 `pu̯o` 相关 -0.04，而与 `po` 相关 0.90**——说明 `pu̯o` 明显偏离标准 bō。

教材里 b p m f 的呼读音是**不圆唇的 o**，写成 `po` 才对；插一个 u 滑动，孩子听到的是「buo」，与同组的 o 卡（ō）也混不上。

### 2.5 正确的部分

**声调没问题。** 全部 64 个音实测基频平稳，都是一声（呼读音口径正确），上一版报告说的「er 读成 ér、ri 读成 rì」在当前 audio 里已不成立（`L_er` 与 `L_ri` 实测均为平调）。

### 2.6 全部 64 个音的判定

## 三、根因：macOS 的中文 IPA 通道能渲染什么、不能渲染什么

用「同一汉字、带 IPA / 不带 IPA」和「同一目标音、多种 IPA 写法」两组对照实验逐条测出来的边界表：

| IPA 成分 | 能否正确渲染 | 证据 |
| --- | :---: | --- |
| `a o e ɤ i u y` | ✅ | 与对应汉字自然读音相关 0.90+ |
| `p pʰ t tʰ k kʰ`（含送气） | ✅ | `pu̯o` vs `pʰu̯o` 相关 0.019，可区分 |
| `m n l f x` | ✅ | 与汉字读音一致 |
| `ts ʈʂ s ʂ ʐ ɕ tɕ`（含翘舌） | ✅ | `ʐi` vs `z̞i` 相关 -0.363；`ʂɨ` vs `sɨ` 相关 -0.009 |
| `˥`（一声调号） | ✅ | 全部实测平调 |
| `i̯ɛ` `u̯e` `i̯o`（非成音节符 + 韵母） | ✅ | ie / ui / iu 均与单韵母可区分 |
| **`ɪ`**（双元音后段） | ❌ | 丢弃 → `aɪ ≡ a`、`eɪ` 截断 |
| **`ʊ`**（双元音后段） | ❌ | 丢弃 → `oʊ ≡ o` |
| **`ɻ`**（卷舌） | ❌ | 丢弃 → `ɤɻ ≡ ɤ` |
| **`ɑ`** `**ɥ**` | ❌ | 整段截断 → ao / üe 只剩 0.19 s |
| **`ʰ` 出现在塞擦音后** | ❌ | 丢弃 → `tɕʰ ≡ tɕ`、`ʈʂʰ ≡ ʈʂ`、`tsʰ ≡ ts` |
| **`ɨ`**（舌尖元音） | ⚠️ | 渲染成清化弱元音（浊音比 0.00–0.17） |
| 拼音正字法（`ai` `b`） | ❌ | 被当字面 IPA 读：`b` 只剩爆破，`ai` 变成两个独立元音 |

**一句话：macOS 能吃「单层、简单」的 IPA，吃不下带修饰符的复杂音素，而且失败时静默。**

### 4.5 `r`：音位是对的，旧版错在调值

**这一条要单独说清楚，因为它容易被反复误修。**

`r` 的两个历史问题要分开记账：

| | 旧版 | 修正版 |
| --- | --- | --- |
| **调值** | ✅ 本来就是 IPA `ʐi˥`（**第一声**，不是四声） | ✅ 同上，没动过 |
| **音位** | ✅ 翘舌起音正确 | ✅ 同上 |
| **元音** | ⚠️ 纯 [i]（F2≈3190），**不是「日」的舌尖元音 [ɨ]**（F2≈2500） | ⚠️ 同样，见下 |

**更正**：本报告早前写「旧版整体认读音节 `ri` 用汉字「日」兜底 → 读成四声 rì」——**这是错的**。逐字节核对确认：**旧版 `L_r` 与 `L_ri` 就是同一个文件，IPA 一直是 `ʐi˥`（第一声）**，新旧完全一致。用户听到的「ri 不对」不是调值问题。

真正没解决的只有**元音**：普通话里 `r / z / c / s / zh / ch / sh` 后面的 i 实际读**舌尖元音 [ɨ]**（和「日」同音），而 Tingting 的 `ʐi˥` 渲染出的是**纯 [i]**（F2 3189，「日」是 2490）。

**但这一条在 Tingting 里无解**：实测「日」的元音 `ɨ / ɻ` 只在 **IPA 不带调符**时才被渲染（`ʐɨ` → F1 207 / F2 2557，与「日」完全一致），而那时调值必定是四声；**一旦加上 `˥`，`ɨ` 就被整段丢掉**（只剩 0.09 s 裸辅音）。也就是说「日的元音 + 平调」在 macOS 的 IPA 通道里**两者不可兼得**。

三个候选的实测对比：

| 方案 | 元音 | 调值平稳度 | 音色 |
| --- | --- | --- | --- |
| **Tingting `ʐi˥`（线上，推荐）** | 纯 [i]，非日的 [ɨ] | **极差 5%，完美平调** | 婷婷，与全卡一致 |
| espeak `ri1` | [ɨ]（F2 1754）✓ | 94→97→187 Hz，**不稳** | 机械音，与全卡不一致 |
| GitHub 真人 `ri1.mp3` | [ɨ]（F2 1850）✓ | 395→368→452 Hz，**起伏 29%** | 真人，但朗读式语调 |

**结论：保留 Tingting `ʐi˥`。** 呼读音的**调值必须干净**（教错调比元音不够地道危害更大），音色统一也更利于连续跟读。若将来整批 21 个声母都换成真人录音，再一并换 `r` / `ri`。

对 r 的可选处理：

| 方案 | 做法 | 效果 |
| --- | --- | --- |
| **维持修正版** | IPA `ʐi˥` | 调值对、音位对，只是翘舌度比真人略欠一点 |
| 换 espeak-ng 的 `ri1` | espeak 输出 `ʐˈi.5` | 音值最准，但音色与其他 62 条不一致 |
| 换 GitHub 真人录音 | `mp3-chinese-pinyin-sound` 的 `ri1.mp3` | 音值准 + 音色自然（但全批换真人会带来音质断层） |

**建议先维持修正版**，等整批 21 个声母都考虑换真人录音时一起处理，别单独换一条。

### 4.6 顺带澄清：`ve ≡ yue` 不是缺陷

韵母 `üe` 与整体认读音节 `yue` 本来就是同一个音 /yɛ/，两者读音相同是正确的。上表里它们仍列为「拼写等价」，不属于错误组。

## 五、另一条路：espeak-ng（本机已装 1.52.0）

它自带 `cmn-latn-pinyin`（拉丁转拼音普通话）语音，我实测过：

**能做的**
- 21 个声母呼读音的**音素全部正确**，包括汉语里没有对应汉字的那 6 个：
  `fo1→fˈo5`、`de1→tˈə5`、`te1→thˈə5`、`ne1→nˈə5`、`le1→lˈə5`、`ri1→ʐˈi.5`
- 双元音、卷舌、ü 全对：`ai1→ˈai5`、`ao1→ˈɑu5`、`er1→ˈər5`、`ü1→ˈy5`
- 四个声调可区分（ma1–ma4 音频各不相同）

**不能做的**
- **不区分平舌/翘舌**：`zha1→ts.ˈɑ5`、`cha1→ts.hˈɑ5`、`sha1→s.ˈɑ5`——`zhi/chi/shi` 会读成 `zi/ci/si`。对这个卡集是**硬伤**，因为「平舌 vs 翘舌」正是它要教的重点，还专门有一组易混对照卡。
- 音色机械，孩子可能不接受
- `--ipa` 直接喂 IPA 输入不工作（会被当英文拼写）；`v` 不代表 ü（要用 `ü` 或 `yu`）

**结论：espeak-ng 适合当交叉校验工具，或只用于那 6 个「无字可读」的声母（f d t n l r），不适合全量替换。**

**但有一个必须知道的坑**：`bo1.mp3` 里的 b 是按「波 bō」的**词**音录的，声母起始比教材呼读音（不送气的轻辅音）重。用于认读跟读够用，**不够做 b/d/p/q 的辨音训练**——而这恰恰是本卡集的「易混对照」组要教的内容。

**因此推荐组合**：

- **主源**：修正版的 Tingting 汉字路线（§4，已 18/18 组教学对立全部通过），只把 `r` 换掉。
- **`r` 替换**：用 `mp3-chinese-pinyin-sound` 的 `ri1.mp3`（真人录制，Unlicense 可商用，已验证可下载、时长 1.07 s）。
- **其余 20 个声母**：可选用 GitHub 真人录音整批替换，音色统一、免费、可商用。
- **韵母**：继续用 Tingting 汉字路线（`o`/`un`/`ong`/`eng` 在 GitHub 源里要么没有、要么音值不对）。
- **交叉校验**：把 GitHub 的 21 个呼读音下载下来，与 `audio_修正版/` 逐条比对，作为「音值对不对」的第三方参照。

## 七、顺带发现

1. **`audio/` 里有 55 个死文件**：`S_` 38 个（旧版拼读卡的「韵母_声母」组合音）、`T_` 16 个（旧版声母+声调）、`L_ü.m4a` 1 个（HTML 引用的是 `L_v`，这个是旧命名残留，且与 `L_v.m4a` 并非同一文件）。当前两套 HTML 都不引用它们。拼读卡现在复用 `L_`，没有 `S_ai` 这类文件。
2. **易混对照音频有拼接缝隙**：`C_bdpq` 等 7 个是用 ffmpeg 把多个 m4a 直接 concat 的，每个 m4a 自身带 AAC 编码延迟，拼接处会插入约 0.08–0.31 s 静音（实测 `C_bdpq` 内部 4 段静音共 0.35 s）。改法：先全部解成 PCM 拼接，再一次性编码（修正版脚本已改）。
3. **现有校验脚本查不出发音问题**：`检查拼音卡.py` 只断言文件存在与时长 ≥ 0.12 s。0.19 s 的坏音频正好卡在阈值之上，必须靠声学指标才能发现。
4. **`拼音卡集说明.md` 里引用的教育部链接已失效**：`hudong.moe.gov.cn/jyb_sjzl/ziliao/A19/195802/t19580201_186000.html` 实测返回 **HTTP 404**。可用的入口是 `https://www.moe.gov.cn/jyb_sy/sy_wb/201301/t20130129_147290.html`。

## 八、本次新增的可复用工具

`检查呼读音.py`（与本目录同级）——用 ffmpeg + numpy 做客观发音体检，不联网、不改文件：

```bash
python3 检查呼读音.py                 # 扫描 audio/ 下全部 L_ / TONE_ / C_
```

输出：时长、浊音比、基频走向判声调、共振峰粗估、内部静音段（判「被读成两段」）。建议把它接进 `检查拼音卡.py`，至少断言：① 每个音形音频时长 ≥ 0.25 s；② 不存在「与另一个音字节相同」且两者不是拼写等价类。

## 九、需要你拍板的三件事

1. **er 用什么？** 「耳」是 3 声（ěr）；教材 `er` 常标 `ér`（2 声）。Tingting 没有第一声的「儿/耳」。可选：接受 ěr / 用 espeak 的 `er1` / 真人录一条。
2. **整体认读音节用第一声吗？** 现行 16 个整体认读音节全部读第一声（`ri` 读 rī、`si` 读 sī）。教材标调号时不标调，课堂也常按第一声教。是否维持现口径。
3. **「完整拼音表 63」保留还是收成一张总览？** 保留则与「整体认读」子集有 16 张重复展示；收成总览则少 63 个逐张入口。
4. **`r` 要不要换成真人录音？** 修正版的 `r` 音色是合成音、翘舌度略欠（§4.5）。换成 GitHub 的 `ri1.mp3`（Unlicense 可商用）能一次解决，代价是音色与另外 62 条不一致。

- `ve ≡ yue` 不是缺陷（üe 与 yue 本就同音 /yɛ/）。
