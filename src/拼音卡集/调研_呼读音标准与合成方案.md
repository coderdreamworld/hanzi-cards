## 0. 结论速览（先看这里）

1. **本目录现有 `audio/` 的 63 条"标准呼读音"里有 7 组文件字节完全相同**，其中 6 组是**教学上必须区分但实际无区分**的错误：`zh=sh=ch`、`a=ai`、`o=ou`、`e=er`、`j=q`、`z=c`；第 7 组 `ve=yue` 的成因是**ü 被丢弃**（旧版读成 ê）。**`L_r`≡`L_ri` 不算错误**——普通话里 r 与 ri 本就是同一个音节（拼写等价类）。这是本次调研最重要的发现，问题在**合成方法**而不是素材。
2. 根因：`AVSpeechSynthesisIPANotationAttribute` 对中文 voice（Tingting）是**部分且有损**的 IPA 支持。IPA 字符串里写进去的音素，**不被识别时会被静默丢弃而不是报错**（与 Azure 的"未知音素返回 400"形成鲜明对比）。
3. **可行解**：本机 `say -v Tingting` 直接读**标准第一声汉字**（58/64 有对应字），只对 6 个没有第一声常用字的音（fō dē tē nē lē rī）用 Tingting 的简单 IPA 形式。这条路线能同时保住翘舌/平舌、送气对立、舌尖元音 ɨ。【转述】**已落地并回归：18/18 组真实教学对立全部通过。**
4. **r 的定性（实测修正）**：r 的**音位本来就是对的**——用**起音段**（去调值混淆）复测，`L_r` 与自然「日」相差 **0.839**，而「日」与平舌「资」差 1.342、与「诗」差 4.006。旧版"r 完全不对"是**调值问题**（用「日」兜底成了四声），不是音位问题；剩下的只是翘舌度略欠。见 §2.1.3b。
5. **教材口径**：2024 修订人教版把 `i u ü y w` 拆成 `i u ü` 与 `y w` 两课，**声母明确为 21 个**（y/w 是零声母音节的书写变通，不算声母）；**单韵母由 8 个精简为 6 个**；教学顺序是"先系统学声母韵母 → 再学整体认读音节"。【查证】
6. **整体认读音节该不该放**：建议**保留但降级**——它们是《汉语拼音方案》明文的整体认读音节，是法定教学内容；但卡片卡面应给"第一声呼读"，并在说明里标注"整体认读音节要整个记住，不能拼读"。【查证 + 结论建议】

## 1.2 声母的呼读音（教学口径）

### 结论

《汉语拼音方案》本身**只规定字母与音位的对应，不规定"呼读音"**；"呼读音"是**课堂教学惯例**，在教材里以"示例汉字 + 注音"呈现。因此呼读音表应分两层给：

**第一层：教材示例字（= 学生先看到听到的）**

| 声母 | 教材示例字（第一声呼读） | 声母 | 教材示例字 |
| --- | --- | --- | --- |
| b | bō 玻 | zh | zhī 知 |
| p | pō 坡 | ch | chī 吃 |
| m | mō 摸 | sh | shī 诗 |
| f | fó 佛（无第一声常用字） | r | rì 日 |
| d | （无第一声常用字，教材用 dé 得 / dē） | z | zī 资 |
| t | （无第一声常用字，教材用 tè 特） | c | cī 疵 |
| n | （无第一声常用字，教材用 nè 讷） | s | sī 思 |
| l | （无第一声常用字，教材用 lè 勒） | | |
| g / k / h | gē 哥 / kē 科 / hē 喝 | | |
| j / q / x | jī 基 / qī 欺 / xī 希 | | |

【查证 + 通行教材实践】2024 修订教材把声母分课教授，课名保留字母组：`《b p m f》`《`《d t n l》`《`《ɑi ei ui》`《`（见上引 PEP PDF 原文 "在《ɑi ei ui》一课中…""在《b p m f》一课中…""在《d t n l》一课中…"）。

**第二层：音位目标（= 合成引擎要产出的声音）**

| 声母 | 目标音值 | 备注 |
| --- | --- | --- |
| b p m f | p / pʰ / m / f | b 在普通话里是**不送气**的 [p⁼]，不是浊 [b] |
| d t n l | t / tʰ / n / l | d 是**不送气** [t⁼] |
| g k h | k / kʰ / x | h 是 [x]，教材常写成 [h] |
| j q x | tɕ / tɕʰ / ɕ | **送气对立必须保住** |
| zh ch sh r | ʈʂ / ʈʂʰ / ʂ / ʐ | **翘舌必须保住** |
| z c s | ts / tsʰ / s | **平舌 + 送气对立必须保住** |

【实测】送气对立（p/b、t/d、k/g、j/q、z/c、zh/ch）与平翘舌（z/zh、c/ch、s/sh）是本卡集的教学核心，PEP PDF 明确列为教材专项训练模块（"专门设置'z / zh''c / ch''s / sh'对比模块"），并给出学习者错误率数据："平翘舌音错误率持续在 **35%—45%**"。→ **合成方案必须在客观上区分这两组对立，不能靠听觉事后判断。**

### fō dē tē nē lē rī 这六个音的标注与教法

- **f**：普通话没有 f 韵尾，**没有** fā/fē/fī 一类第一声常用字。教材用"佛"(fó) 演示 f 的**音位**（唇齿清擦音），或用"飞/风"作拼读练习。教学时明确告诉孩子：**f 是双唇上齿轻咬发出的摩擦音，读的时候上牙要碰下唇**。
- **d / t / n / l**：教材用"得"(dé)/"特"(tè)/"讷"(nè)/"勒"(lè) 演示**音位**，但**呼读时教师要把它们读成第一声**（dē tē nē lē），因为"呼读音"的作用是让声母的**本音**清晰可辨，教学时用第一声最不容易走样。
- **r**：普通话没有独立 r 韵母，**没有** rī 一类常用字。教材用"日"(rì) 演示，r 的音位是**舌尖后浊擦音 ʐ**。

【查证待补】以上"教材用某某字演示"的逐条对应关系，应以**人教版一年级上册教师用书/教师教学用书**的注音栏为准；本报告的对应表基于通行教材实践与 PEP PDF 中出现的课名与例词（`《d t n l》`课、"爸""妈""书"等选词），**具体到每个字母的注音栏仍需查教师用书原件**。这是本报告标注为【待核】的唯一一处教材细节缺口。

## 1.3 r 的发音部位

- **权威口径**：r 是**舌尖后浊擦音 ʐ**（retroflex voiced fricative），发音部位与 zh/ch/sh 同为**翘舌**（舌尖上翘抵住硬腭前部），但**声带振动、不阻塞气流**。它**不是**卷舌的 er（er 是舌尖元音 ɻ + 卷舌动作）。
- 【查证】维基百科「汉语拼音」条目记载：er 属**单韵母**，"发音为单韵母'er'（注音符号 ㄦ）的字（如：儿、尔、耳）做韵尾时的音变为 r"——即 r 与 er 的区别在于 **r 是舌尖后浊擦音（可作韵尾）**，er 是舌尖元音 + 卷舌。
- 【待核】《现代汉语词典》第 7 版 r 字的词条原文（"翘舌浊擦音"表述与注音 `ㄖ`）需查词典原件核对。
- **教学说法（可写进卡片文案）**："r 翘着舌头发音，声带要振动，像嗓子眼里轻轻磨出来的声音；跟 er 完全不同，er 是在 ei 的口型上卷舌。"

## 1.4 单韵母 o 的标准音值

- 【待核 + 通行音系】o 的音值是**后半高元音**，比 [ɔ] 略前、略高，接近 **[o]**（不是开口度很大的 [ɔ]，也不是 card. 的 [ɒ]）。教材注音栏写作 **ō**。
- **「喔 / 哦 / 噢」哪个更接近标准呼读音**：
  - **喔**（ō/ò）— 最接近。后半高圆唇后元音，正是标准 o。
  - **噢**（ō）— āo 韵的**零声母**音节，实际音值是 [o]，但拼写上带 a，更接近 ao 的 o。
  - **哦**（ó/ò）— 口语常用，字面读音也接近 [o]，但使用频率低、易被读成 [ə]。
  - **结论**：**首选「喔」**，次选「噢」。合成时应直接产出 [o]，不要用"哦"。
- 【查证】PEP PDF 记录 2024 修订把**单韵母由 8 个精简为 6 个**（去掉 ê），说明 o 是保留的 6 个单韵母之一（a o e i u ü）。

## 1.5 ü 的呼读音与 y 的写法

- **标准音值**：ü 的音值是**前高圆唇元音 [y]**（不是 [u]，也不是 [ɨ]）。ü 只在 j q x y 后写 ü（jü qu xu yu），其余位置写 u（nü lü 写成 nu lu）。
- **教学上的标准说法**：ü **单独成音节时读"迂"（yū）**，是一个**独立的圆唇前高元音**；ü 是**撮口呼**（唇形小而圆，舌位前）。
- 【查证】维基百科引《汉语拼音方案》：韵母按口形分"四呼"，ü 属**撮口呼**，与开口呼（a、o、e、ê）、齐齿呼（i）、合口呼（u）并列。
- **与 y 的区别**（教学讲法）：**y 不是声母**，是 i 行零声母音节的**书写符号**。y 在 ü 行的三个音节（yu/yue/yuan）里读的是**ü 本音**；y 在 i 行（yi/ye/yin/ying）里读的是 i。→ 教材已经把这件事讲清楚：2024 修订版把 `i u ü` 与 `y w` **拆成两课**，先学韵母本音，再讲 y/w 的**拼读规则**（PEP 官网原文："将难度较大的拼音课'i u ü y w'拆分为'i u ü'和'y w'2课"）。
- **合成口径**：ü 卡的音频必须是 **[y]（撮口呼）**，不能是 [i] 也不能是 [u]。

## 1.6 16 个整体认读音节

- 【查证】《汉语拼音方案》明文规定这 16 个为**整体认读音节**：zhi chi shi ri / zi ci si / yi wu yu / ye yue yuan / yin yun ying。
- 【查证】课程标准（2022）第一学段要求原文（经 PEP PDF 转引核对）：**"学会汉语拼音。能读准声母、韵母、声调和整体认读音节。能准确地拼读音节，正确书写声母、韵母和音节。"**
- 【查证】教学顺序：PEP PDF 原文——"采用**先系统学习声母、韵母，后逐步学习整体认读音节**的渐进式设计"；"拼音单元的数量由两个增加到三个"。
- **教学上整体认读音节与"声母+韵母"的音节调值是否一样？**
  - **不一样，而且必须不一样。** 整体认读音节的调由**音节本身承载**（如 zhī 是 zhī，不是 zh+ī 的拼合），所以一张 zhī 卡就应当读成第一声 ō 级别的 zhī，而不是"拼读出来的 zhī"。
  - 教材呈现上，整体认读音节是**整卡出现、整个记住**，不拆成声母卡 + 韵母卡。
  - 实践含义：**做卡片时整体认读音节的音频必须是"单音节、完整调值"**，不能是"声母音 + 韵母音"两段拼接。→ 这一点直接否定了"用声母卡拼出 zhī 卡"的省事做法。

## 1.7 er（特殊韵母）

- 【查证】er 在《汉语拼音方案》里**归入单韵母**（维基条目："发音为单韵母'er'（注音符号 ㄦ）的字（如：儿、尔、耳）"），2024 修订教材把单韵母精简为 6 个时 **er 保留**（去掉的是 ê）。
- **调值**：er 是**零声母音节**，调值随所拼的词（ ér 儿、èr 饿）；教材注音写 **ér**（注音符号 ㄦ，教材通常标作 ér / ēr 的轻声变体）。
- **卷舌动作要求**：读 er 时**先摆好 e（舌位前、嘴角展开）的口型，再把舌尖上翘（卷舌）**，舌尖不抵住硬腭（这是与 zh/ch/sh 翘舌音的本质区别）。
- 【待核】教材注音栏的确切写法（"ér"还是"ēr"）需查教师用书；本文按通行的 **ér** 表述。

## 1.8 拼音字母卡里该不该放 yue / ying 这类完整音节？

- **事实**：yue / ying 属于**整体认读音节**，是《汉语拼音方案》法定内容、课程标准要求、教材必教。【查证】
- **结论建议**：
  1. **保留**，但**分层**：把它们放在"整体认读"子集，卡面用**整音节 + 第一声呼读**，并在卡上写清"**整体认读音节，要整个记住，不用拼**"。
  2. **不要**把 yue/ying 混进"韵母"子集——它们不是韵母，是完整音节；混进去会破坏"韵母=韵头+韵腹+韵尾"的结构认知。
  3. **不要**用"声母+韵母"两张卡拼出来的两段音频充当 yue/ying 的音频（见 1.6 的调值论证）。
  4. 本卡集当前的结构（声母 21 / y·w 2 / 韵母 24 / 整体认读 16 / 完整拼音表 63 / 声调五类 / 易混对照）**与教材的三单元、渐进式顺序一致，是合理的**，建议保留。

# 二、发音合成方案对比

## 2.1 方案 A：macOS `AVSpeechSynthesizer` + IPA 属性（本目录现有做法）——**实测结论：不可用作唯一来源**

### 2.1.1 Apple 官方声明

【查证】Apple SDK 头文件 `AVFAudio.framework/Headers/AVSpeechSynthesis.h`（本机 `xcrun --show-sdk-path` 实测，第 53–54 行）：

```objc
//NSString, containing International Phonetic Alphabet (IPA) symbols. Controls pronunciation of a certain word or phrase, e.g. a proper name.
extern NSString *const AVSpeechSynthesisIPANotationAttribute API_AVAILABLE(ios(10.0), watchos(3.0), tvos(10.0), macos(10.14));
```

**官方措辞只有一句"控制某个词或短语的发音，例如人名"，没有承诺支持任何具体音素表，更没有承诺支持中文。**

### 2.1.2 实测：IPA 属性确实生效，但**不认识的音素被静默丢弃**

【实测】方法：同一文本 + 不同 IPA 串 → 生成 → 24 段 log-mel 频谱做时域对齐后取平均绝对差；**距离 0.000 = 输出完全相同**。

**决定性证据（IPA 完全覆盖文本）**：
- `衣` + `a˥` 与 `妈` + `a˥` 输出**完全相同**（d=0.000）→ 文本被 IPA 覆盖。
- `衣` + `a˥` 与 `衣` 无 IPA 输出**不同** → IPA 确实生效。

**音素丢弃矩阵（实测）**：

| IPA 符号 | 结果 | 证据 |
| --- | --- | --- |
| `a o ɤ i u y ɛ ə ɑ ɨ` | ✅ 生效 | 与自然字读音匹配 |
| `p pʰ t tʰ k kʰ m n l f x` | ✅ 生效 | 送气对立可测（d=2.5~3.3） |
| `ts s ʂ ɕ tɕ ʐ` | ✅ 生效 | 音段可测差异 |
| `˥`（一声） | ✅ 生效 | `日` 无 IPA 斜率 −0.447（rì 降调）；`日`+`ʐi˥` 斜率 +0.002（平调） |
| `˥˩`（四声）、`˩˥`（三声） | ✅ 生效 | F0 曲线正确 |
| `˧˥`（二声） | ❌ **不升调** | `妈`+`ma˧˥` F0：225→195→225，**呈降升**，不是二声升调 |
| `ɪ ʊ`（双元音后段） | ❌ **静默丢弃** | `aɪ˥` ≡ `a˥`（d=0.000）；`oʊ˥` ≡ `o˥`（d=0.000） |
| `ɻ`（卷舌） | ❌ **静默丢弃** | `ɤɻ˥` ≡ `ɤ˥`（d=0.000） |
| `ɥ`（撮口呼） | ❌ **静默丢弃** | `ɥɛ˥` ≡ `ɛ˥`（d=0.000）；单独 `ɥ` → 0.012 s 近乎静音 |
| `ʈ`（舌尖后塞音） | ❌ **静默丢弃** | `ʈʂɨ˥` ≡ `ʂɨ˥`（d=0.000） |
| `ʰ`（塞擦音后的送气） | ❌ **静默丢弃** | `tɕʰi˥` ≡ `tɕi˥`（d=0.000）；`tsʰɨ˥` ≡ `tsɨ˥`（d=0.000） |
| `ʐ`（舌尖后浊擦音） | ⚠️ **与 `r` 不区分，但音位正确** | `ʐi˥` ≡ `ri˥`（d=0.000）→ 解析器把 ʐ 归到引擎自己的 `r`；但**中文语音里这个 `r` 就是普通话的翘舌音**（见 2.1.3 的起音段验证），不是英语 r |
| `ɨ`（舌尖元音） | ⚠️ 弱化/清化 | 浊音比 0.00–0.17，而正确汉字读音为 0.51–0.76 |

### 2.1.3b r 的音位是否真的丢了？——**起音段（去调值混淆）复测**

【实测】上一版报告曾把 `L_r`（第一声）与自然「日」(rì，**四声**) 整段对比，得 d=2.299，并据此写成"r 是唯一遗留妥协"。**这个对比有缺陷：调值差异被混进了音位差异。**
正确做法是**只比起音段**（发音部位线索所在的前 90 ms），调值自然被排除。

**【实测】起音段（90 ms）log-mel 距离：**

| 对比 | d | 读法 |
| --- | ---: | --- |
| **`L_r` vs 日（真 ʐ）** | **0.839** | **最接近自然 ʐ** |
| `L_r` vs 资（平舌 ts） | 1.253 | 明显更远 |
| `L_r` vs 丝（平舌 s） | 1.363 | 明显更远 |
| `L_r` vs 知（ʈʂ） | 2.108 | 更远 |
| `L_r` vs 诗（ʂ） | 4.139 | 最远 |
| — 标尺 — | | |
| 日 vs 资 | 1.342 | 自然 ʐ 与平舌的距离 |
| 日 vs 诗 | 4.006 | 自然 ʐ 与 ʂ 的距离 |
| 日 vs 知 | 1.944 | 自然 ʐ 与 ʈʂ 的距离 |

**结论（修正）**：
1. **Tingting 的 IPA `ʐ`/`r` 渲染出的就是普通话的翘舌音**，不是英语 r。解析器把 `ʐ` 与 `r` 归一到同一个音位（输出字节相同），但该音位在中文语音里本来就是 ʐ。
2. `L_r` 的起音与自然「日」相差 0.839，而「日」与平舌「资」相差 1.342、与「诗」相差 4.006 → **`L_r` 明显是翘舌，且只比自然 ʐ 略欠一点翘舌度**（位置约在"日 vs 资"的边界上）。
3. **因此 r 的音位没有问题，剩余只是一点点翘舌度不足。** 若要再提升，优先用真人录音（见 §2.6）。
4. **r 的两个历史问题要分开记账**：
   - 旧版 `L_r` / `L_ri` 用汉字「日」兜底 → 四声，**是调值问题**；
   - 旧版 `L_r` 用 IPA `ʐi˥` → **音位本来就对**。
   → **"r 完全不对"是调值问题，修正版已解决；剩下的只是翘舌度。** 以后不要再把这两件事当成同一个 bug。

**❌ 硬伤 1：不区分平舌 / 翘舌**

→ zhi/chi/shi 会被读成 zi/ci/si。**这恰恰是教材最强调、错误率 35–45% 的那组对立。**

**❌ 硬伤 2：不能只用单个字母，必须带韵母**
```
b1 → (en)bˈiː5(cmn)     ← 回退成英文 "bee"
```

**❌ 硬伤 3：不能用 `--ipa` 直接喂 IPA 输入**
```
$ espeak-ng -v cmn-latn-pinyin --ipa "f-o"
(en)ˈɛ5fˈəʊəʊ(cmn)      ← 当成两个英文字母读
```
→ espeak-ng **没有** "IPA 作为输入" 的能力，只能用它自己的拼音正字法。

**❌ 硬伤 4：`v` 不代表 ü**
```
v1 → (en)vwˈɒ5n(cmn)      ← 回退成英文 "von"
ve1 → (en)vɛ5wˈɒ5n(cmn)
```
→ 必须写 **`ü1` / `üe1`** 或 **`yu1`**。（`vn1` 同样失败，ün 要写 `ün1`。）

**⚠️ 音色**：espeak-ng 是**共振峰合成**，机械感明显，音质远低于 Tingting/神经 TTS。【实测波形特征：短时长、基频平直、机械感】**对 4 岁孩子的接受度是主要风险。**

- **声母 21 + 整体认读音节 16 可以整批换成真人录音**（这正是把 r 的翘舌度补到满分的最佳路径）；
- **韵母不能整批换** —— `o` / `un` / `ong` / `eng` / `ui` / `iu` / `ie` 必须走合成（Tingting 汉字）或人工补录；
- 真人录音与合成混用时，**必须用 §3.3 的 mel 距离交叉比对**，防止两条路线的音互相矛盾（例如真人 `o1` 是 [o] 而合成 `ou` 里的 o 是 [oʊ] 前段）。

**注意授权与音质**：采用他人录音前需确认仓库许可；真人录音的响度/底噪与合成片不同时，必须统一到 -16 LUFS / ≤ -1 dBTP 并做 §4.3 的降噪处理，否则同一张卡组里会出现明显音质断层。

## 3.2 声调检验：基频曲线分 5 段算 T1–T5

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""拼音音频客观验收：基频分 5 段 + 静音检测 + 音节切分。纯 numpy，无第三方依赖。"""
import subprocess, sys, wave
from pathlib import Path
import numpy as np

SR = 16000

def to_wav(src: Path, dst: Path) -> Path:
    if src.suffix == ".wav":
        return src
    subprocess.run(["ffmpeg", "-loglevel", "error", "-y", "-i", str(src),
                    "-ar", str(SR), "-ac", "1", str(dst)], check=True)
    return dst

def load(path: Path):
    w = wave.open(str(path), "rb")
    n, sr = w.getnframes(), w.getframerate()
    d = np.frombuffer(w.readframes(n), dtype=np.int16).astype(np.float64) / 32768.0
    w.close()
    return d, sr

def f0_track(d, sr, fmin=70, fmax=420, hop=0.010, win=0.040):
    """自相关基频轨迹；无声/低能量帧记 0。"""
    W, H = int(win * sr), int(hop * sr)
    t, f, e = [], [], []
    for i in range(0, max(1, len(d) - W), H):
        seg = d[i:i + W]
        rms = float(np.sqrt(np.mean(seg ** 2)))
        e.append(rms)
        if rms < 0.012:
            t.append(i / sr); f.append(0.0); continue
        s = (seg - seg.mean()) * np.hanning(W)
        c = np.correlate(s, s, "full")[W - 1:]
        c /= (c[0] + 1e-12)
        lo, hi = int(sr / fmax), int(sr / fmin)
        hi = min(hi, len(c) - 1)
        if hi <= lo:
            t.append(i / sr); f.append(0.0); continue
        k = lo + int(np.argmax(c[lo:hi]))
        if 0 < k < len(c) - 1:
            a, b, cc = c[k - 1], c[k], c[k + 1]
            den = a - 2 * b + cc
            if abs(den) > 1e-9:
                k = k + 0.5 * (a - cc) / den
        t.append(i / sr); f.append(sr / k if k > 0 else 0.0)
    return np.array(t), np.array(f), np.array(e)

def clean_f0(f0, iters=4):
    """修正自相关的倍频/半频跳变。

    自相关在起音、塞音爆破和摩擦噪上极易出现 2 倍、4 倍、1/2 倍的八度跳变
    （实测 Tingting 的 'ma˥' 末尾会出现 393 Hz，而真实基频约 98 Hz）。
    做法：反复以整条轨迹的中位数为参考，把每个帧吸附到最接近参考值的八度。
    """
    for _ in range(iters):
        v = f0[f0 > 0]
        if len(v) == 0:
            return f0
        M = float(np.median(v))
        out = []
        for x in f0:
            if x <= 0:
                out.append(0.0)
                continue
            best = min([x, x / 2, x / 4, x * 2, x * 4],
                       key=lambda c: abs(np.log(c / M)))
            out.append(best if abs(best - M) / M < 0.45 else x)
        f0 = np.array(out)
    return f0

def tone_class(f0):
    """按基频相对走向判定调类。返回 (类别, 分段相对音高, 首末差, 有效帧数)。

    关键点：归一化必须用 **固定参考跨度**（整条轨迹中位数 × 0.45），
    不能用观测到的 max-min。否则 3 Hz 的漂移会被放大成 [0, 1]，
    平调会被误判成升调（实测踩过这个坑）。
    """
    idx = [i for i, x in enumerate(f0) if x > 0]
    if len(idx) < 6:
        return "太短-无法判定", [], 0.0, len(idx)
    v = f0[idx[0]:idx[-1] + 1]
    k = int(len(v) * 0.12)                      # 掐掉首尾 12% 的起音/收音不稳段
    v = v[k:len(v) - k] if len(v) - 2 * k >= 6 else v
    v = clean_f0(v)
    v = v[v > 0]
    if len(v) < 6:
        return "太短-无法判定", [], 0.0, len(v)
    nseg = 5 if len(v) >= 25 else 3
    rel = [float(np.median(s)) for s in np.array_split(v, nseg) if len(s)]
    ref = float(np.median(v))
    half = max(ref * 0.45, 1.0)
    norm = [(x - ref) / half for x in rel]
    first, mid, last = norm[0], norm[len(norm) // 2], norm[-1]
    spread = max(norm) - min(norm)
    if mid < min(first, last) - 0.12:
        cls = "T3(降升)"
    elif last - first > 0.22:
        cls = "T2(升)"
    elif first - last > 0.22:
        cls = "T4(降)"
    elif spread < 0.34:
        cls = "T1(平)"
    else:
        cls = "T5/其他"
    return cls, [round(x, 3) for x in norm], round(last - first, 3), len(v)

def internal_silence(d, sr, thresh_db=-40, min_gap=0.045):
    """找音节**内部**的异常静音（>45 ms）。返回 (静音段列表, 静音总时长)。

    注意：Tingting / ffmpeg 输出的首尾通常有几十毫秒的静音衬垫，
    那不是"被读成两个音"，必须排除掉首尾段，只保留真正的中间断点。
    """
    W, H = int(0.020 * sr), int(0.005 * sr)
    rms = []
    for i in range(0, max(1, len(d) - W), H):
        seg = d[i:i + W]
        rms.append(float(np.sqrt(np.mean(seg ** 2))))
    rms = np.array(rms)
    if rms.max() <= 0:
        return [], 0.0
    db = 20 * np.log10(np.maximum(rms, 1e-9) / rms.max())
    quiet = db < thresh_db
    segs, start = [], None
    for i, q in enumerate(quiet):
        if q and start is None:
            start = i
        elif not q and start is not None:
            segs.append((start * 0.005, i * 0.005)); start = None
    if start is not None:
        segs.append((start * 0.005, len(quiet) * 0.005))
    segs = [(a, b) for a, b in segs if b - a >= min_gap]
    # 去掉首尾衬垫：贴着 0 或贴着文件末尾的静音段不算内部断点
    total = len(d) / sr
    internal = [(a, b) for a, b in segs if a > 0.02 and b < total - 0.02]
    return internal, sum(b - a for a, b in internal)

def report(path: Path, expect_tone="T1"):
    wav = to_wav(path, Path("/tmp/_verify.wav"))
    d, sr = load(wav)
    dur = len(d) / sr
    t, f0, e = f0_track(d, sr)
    cls, norm, slope, nframes = tone_class(f0)
    sil, sil_dur = internal_silence(d, sr)
    print(f"{path.name}")
    print(f"  时长        : {dur:.3f} s")
    print(f"  峰值        : {float(np.max(np.abs(d))):.3f}")
    print(f"  浊音段      : {int((f0>0).sum())} 帧 / 共 {len(f0)} 帧")
    print(f"  声调判定    : {cls}   分段相对音高={norm}  首末差={slope:+.3f}  有效帧={nframes}")
    if expect_tone and cls not in ("太短-无法判定", "T5/其他") and not cls.startswith(expect_tone[:2]):
        print(f"  [警告] 期望 {expect_tone}，实测 {cls}")
    print(f"  内部静音段  : {[(round(a,3), round(b,3)) for a,b in sil]}  合计 {sil_dur:.3f} s")
    if sil_dur > 0.045:
        print("  [警告] 疑似被读成两个音（音节中间有异常静音）")
    # 单音节不应有 >1 段明显静音
    if len(sil) >= 2:
        print("  [警告] 出现多段静音，可能被读成多个音节")
    if dur < 0.15:
        print("  [警告] 时长过短，可能音素被丢弃成静音")
    return cls, sil

if __name__ == "__main__":
    for p in sys.argv[1:]:
        report(Path(p))
        print()
```

```bash

```

**判读规则（含实测得出的限制，务必读）**：

1. **适用范围**：只有 `L_*` 单音节卡片适用本脚本的声调判据。`TONE_*`（讲解句）和 `C_*`（拼接对照）**不适用**，它们内部本来就有静音和多个音节——脚本对 `TONE_2.m4a` 会报"多段静音"，这是正确行为，不是缺陷。
2. **单音节判定**：`内部静音段` 必须为空或总时长 < 45 ms；有 ≥2 段静音说明被读成了两个音节（例如 zh 被读成 z + h）。
3. **时长红线**：单韵母卡 0.20–0.45 s；声母呼读音卡 0.28–0.45 s；整体认读音节卡 0.28–0.45 s。**低于 0.15 s 一律判失败**（说明音素被丢弃成静音）。
4. **声调判据只用于"一致性"，不用于"绝对调值"**。实测：
   - espeak-ng 的 `ma1`(平) → 判 T1 ✓；`ma2`(升) → T2 ✓；`ma4`(降) → T4 ✓；
     但 `ma3`(降升) 因起伏太浅被判成 T1、`ma5`(轻声) 被判成 T2 —— **短促孤立音节的降升/轻声无法可靠区分**。
   - Tingting 的 `ma˥` → T1 ✓、`ma˥˩` → T4 ✓；但 `ma˧˥` 被判成 T1、`ma˨˩˥` 被判成 T2 —— 与 2.1.2 的结论一致（**Tingting 的二声调符不升调、三声调符只体现后半段上升**）。
   - Tingting 读孤立韵母时**本身带约 20% 的上扬趋势**（实测 `ɤ`/`ɤɻ` 的 F0 从 246 Hz 升到 296 Hz），因此"卡片＝一声"**不等于基频绝对平**。
   → **结论：卡片音频的声调验收应看"全组是否同形"（一致性）+ 人工试听，而不是看单条是否严格平。**
5. **送气/不送气、平舌/翘舌的对立**，用 3.1 的 MD5 + 3.3 的 mel 距离判定，**不要靠听感**（本项目已经因为这一点翻过车：7 对音频字节完全相同）。

## 3.3 音段时长比例 & 两音素距离（判定"送气/翘舌对立是否保住"）

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""两条拼音音频的 log-mel 距离：距离≈0 说明它们其实是同一个音。"""
import subprocess, sys, wave
from pathlib import Path
import numpy as np

SR = 16000

def load_wav(p: Path):
    tmp = Path("/tmp/_cmp.wav")
    subprocess.run(["ffmpeg", "-loglevel", "error", "-y", "-i", str(p),
                    "-ar", str(SR), "-ac", "1", str(tmp)], check=True)
    w = wave.open(str(tmp), "rb")
    n, sr = w.getnframes(), w.getframerate()
    d = np.frombuffer(w.readframes(n), dtype=np.int16).astype(np.float64) / 32768.0
    w.close()
    return d, sr

def mel_fb(nfft=512, nmel=24, sr=SR, fmin=50, fmax=7500):
    hz2mel = lambda f: 2595 * np.log10(1 + f / 700)
    mel2hz = lambda m: 700 * (10 ** (m / 2595) - 1)
    pts = mel2hz(np.linspace(hz2mel(fmin), hz2mel(fmax), nmel + 2))
    b = np.floor((nfft + 1) * pts / sr).astype(int)
    fb = np.zeros((nmel, nfft // 2 + 1))
    for i in range(nmel):
        l, c, r = b[i], b[i + 1], b[i + 2]
        c = max(c, l + 1); r = max(r, c + 1)
        fb[i, l:c] = (np.arange(l, c) - l) / (c - l)
        fb[i, c:r] = (r - np.arange(c, r)) / (r - c)
    return fb

FB = mel_fb()

def logmel(d, sr):
    W, H = int(0.032 * sr), int(0.010 * sr)
    if len(d) < W:
        return np.zeros((1, FB.shape[0]))
    frames = []
    with np.errstate(divide="ignore", invalid="ignore", over="ignore"):
        for i in range(0, len(d) - W + 1, H):
            P = np.abs(np.fft.rfft(d[i:i+W] * np.hanning(W), 512)) ** 2
            frames.append(np.log(np.maximum(FB @ P, 1e-10)))
    return np.array(frames)

def mel_distance(a: Path, b: Path) -> float:
    da, sa = load_wav(a); db, sb = load_wav(b)
    A, B = logmel(da, sa), logmel(db, sb)
    n = min(len(A), len(B))
    if n < 3:
        return 999.0
    A = A[:n] - A[:n].mean(); B = B[:n] - B[:n].mean()
    return float(np.mean(np.abs(A - B)))

PAIRS = [("zh", "sh"), ("zh", "ch"), ("sh", "ch"), ("z", "zh"), ("c", "ch"), ("s", "sh"),
         ("j", "q"), ("z", "c"), ("b", "p"), ("d", "t"), ("g", "k"),
         ("a", "ai"), ("a", "ao"), ("e", "ei"), ("o", "ou"), ("u", "v"), ("ie", "ve"),
         ("e", "er")]

# 下面这些"看起来该对立、其实本来就同音"，不要放进 PAIRS：
#   ve(üe 韵母) 与 yue(整体认读音节) 在普通话里都是 /yɛ/ —— 距离 0.000 是正确的
EXPECTED_SAME = [("ve", "yue")]

if __name__ == "__main__":
    root = Path(sys.argv[1]) if len(sys.argv) > 1 else Path("audio")
    THRESH = 0.35   # 经验阈值：<0.35 视为"听起来一样"，必须排查
    bad = 0
    for x, y in PAIRS:
        pa, pb = root / f"L_{x}.m4a", root / f"L_{y}.m4a"
        if not (pa.exists() and pb.exists()):
            continue
        d = mel_distance(pa, pb)
        flag = "❌ 相同" if d < THRESH else "✅"
        if d < THRESH:
            bad += 1
        print(f"{flag} d(L_{x}, L_{y}) = {d:.3f}")
    for x, y in EXPECTED_SAME:
        pa, pb = root / f"L_{x}.m4a", root / f"L_{y}.m4a"
        if pa.exists() and pb.exists():
            print(f"➖ d(L_{x}, L_{y}) = {mel_distance(pa, pb):.3f}  （本来就同音，不算失败）")
    print(f"\n共 {len(PAIRS)} 对，应对立 {bad} 对失败")
    sys.exit(1 if bad else 0)
```

## 3.5 整体验收流程（建议写进构建脚本尾部）

```
1. md5 去重      → 6 组必须互不相同：zh/sh/ch、j/q、z/c、a/ai、o/ou、e/er
                     ※ `L_r`≡`L_ri`、`L_ve`≡`L_yue` 属「拼写等价类」（普通话里本就同音），**相同是正确的**，不要报警
                     ※ ü/üe 的正确性**不能靠内部对比检验**（ve 和 yue 本来就同音），
                       必须拿外部参照字比：修正版 L_ve vs 自然「约」= 4.567（远大于阈值，说明 ü 没丢）
2. mel 对立距离  → 全部 ≥ 0.35
3. 声调/静音     → 全部 T1、内部静音 < 45 ms、时长 ∈ [0.15, 0.6] s
4. 响度/峰值     → **每条 RMS ∈ [-21.5, -16.5] dBFS**，true peak ≤ -1.0 dBTP
                    （⚠️ **不要用 EBU 积分响度做卡片素材的判据**，见 §4.2b）
5. 编码          → AAC-LC / m4a，48 kHz，≥ 64 kbps，faststart
```

## 3.6 线上 `audio/` 的响度实测（2026-10-31）

【实测】全部 75 个文件（63 卡片 + 5 声调 + 7 对照）：

| 分组 | 条数 | RMS（dBFS） | RMS 均值 | σ | True peak（dBTP） |
| --- | ---: | --- | ---: | ---: | --- |
| `L_*` 单音节卡 | 63 | -21.1 ~ -17.0 | -18.8 | 0.92 | -11.2 ~ -4.0 |
| `TONE_*` 声调讲解 | 5 | -19.7 ~ -19.0 | -19.4 | 0.28 | -4.7 ~ -3.1 |
| `C_*` 易混对照 | 7 | -18.9 ~ -17.6 | -18.3 | 0.41 | -5.4 ~ -3.6 |
| 全部 | 75 | -21.1 ~ -17.0 | **-18.8** | 0.88 | **-11.2 ~ -3.1** |

**判定**：
- ✅ **组内一致性极好**（L_* 组 σ=0.92 dB，极差 4.1 dB）→ 连续翻卡时听感均匀，不会忽大忽小。**这是最要紧的一条，已达标。**

# 四、录制与后期规范（真人录音路线）

## 4.1 录音规格

| 项目 | 规格 | 依据 |
| --- | --- | --- |
| 麦克风 | 指向性电容（枪式/小振膜）或心形动圈；**离嘴 15–20 cm**，略偏 15° 防喷音 | 避免气流噪声与齿音 |
| 防喷 | 麦克风与嘴之间挂防喷罩 | s/sh/f 的气流很强 |
| 房间 | 窗帘/地毯等软装，避开硬墙混响；录音时关窗关空调 | 混响会让辅音段边界糊掉 |
| 格式 | **48 kHz / 24 bit / 单声道 WAV**（PCM） | 后期降噪与重采样有余量 |
| 电平 | 峰值不超过 -6 dBFS，避免削波 | 削波后降噪会出音乐噪声 |
| 每条时长 | 声母呼读音 0.4–0.6 s；韵母 0.5–0.7 s；整体认读音节 0.5–0.7 s | 留出剪裁余量 |
| 收音方式 | 每条**前后各留 0.5 s 静音** | 便于自动检测切分点 |
| 录制顺序 | 一条一条录，每条之间说"停"；或者整段连录后期按静音切 | 后期切分更准 |

## 4.2 响度标准（二选一）

| 用途 | 目标响度 | 真峰值 | 依据 |
| --- | --- | --- | --- |
| **本卡集推荐（网页内嵌）** | **-16.0 LUFS ±1.0** | **≤ -1.0 dBTP** | Apple Podcasts 立体声标准；网页播放也以此为业界参考 |
| 广播/EBU R128 | -23.0 LUFS ±0.5 | ≤ -1.0 dBTP | EBU R128 通用响度 |

**测量**：
```bash
ffmpeg -hide_banner -nostats -i in.m4a -af ebur128=peak=true -f null - 2>&1 | tail -20
```
（看 `Integrated loudness` / `True peak` / `LRA` 三行。）

## 4.2b ⚠️ 卡片级短素材**不能用 EBU 积分响度做判据**（实测坑）

【实测】本卡集每条只有 **0.19–0.45 s**，而 EBU R128 的积分响度需要**至少 400 ms 的测量窗**、门限（absolute gate -70 LUFS + relative gate）才能打开。对短片段：

```bash
$ ffmpeg -i audio/L_a.m4a -af ebur128=peak=true -f null -   # L_a 只有 0.194 s
  Integrated loudness:
    I:         -70.0 LUFS      ← 门限没打开，报的是静音值，不是真实响度
    Threshold:   0.0 LUFS
  True peak:
    Peak:       -5.6 dBFS      ← 真峰却是正常的
```
`loudnorm` 同样报 `input_i: "-inf"`。**照抄 -16 LUFS 的验收脚本去量，会得出"全部 75 条都不达标"的错误结论。**

**可行的两条路**：

| 方法 | 做法 | 适用 |
| --- | --- | --- |
| **A（推荐）用 RMS 做判据** | `ffmpeg -i f.m4a -af astats=metadata=1 -f null -` 取 `RMS level dB`，配 `True peak` | 短素材、工具无关、稳定可复现 |
| **B 用积分响度** | **必须先循环补足**再量：`-stream_loop 30 -t 4` | 需要与广播标准对齐时 |

```bash
# A：RMS + 真峰（推荐用于卡片素材）
for f in audio/*.m4a; do
  echo "$f $(ffmpeg -hide_banner -nostats -i "$f" -af astats=metadata=1 -f null - 2>&1 \
        | awk '/Peak level dB/{p=$NF} /RMS level dB/{r=$NF} END{print r, p}')"
done
# 输出: <RMS dBFS> <Peak dBFS>

# B：积分响度（先补足到 4 s）
ffmpeg -hide_banner -nostats -stream_loop 30 -i audio/L_a.m4a -t 4 \
  -af ebur128=peak=true -f null - 2>&1 | awk '/^ +I:/{i=$2} /^ +Peak:/{p=$2} END{print i, p}'
```

> **对 B 的补充警告**：【实测】用"循环测量值"回填去归一原始短片，**结果会超调**：7 个抽样里 6 个落在 -17.0~-17.3 LUFS，但 `L_d` 冲到 **-13.8 LUFS**（目标 -17）。原因是循环后的积分响度与单次片段的积分响度不等价。
> → **短素材要做归一，用单遍 `loudnorm=I=...` 并以 RMS 实测做交叉校验，不要迷信两遍法。**

## 4.3 ffmpeg 后处理模板

### 4.3.1 降噪 + 均衡 + 响度归一 + 转 m4a（一步到位）

```bash
# in.wav → out.m4a
# 说明：
#   highpass=f=70   去低频隆隆声
#   afftdn          传统降噪（无模型依赖）；arnndn 效果更好但需要 .onnx 模型
#   loudnorm        两遍模式：先用 print_format=json 测，再用 measured_* 回填
ffmpeg -hide_banner -y \
  -i raw.wav \
  -af "highpass=f=70, \
      afftdn=nr=12:nf=-30, \
      dynaudnorm=f=150:g=9, \
      loudnorm=I=-16:TP=-1.0:LRA=11" \
  -ar 48000 -ac 1 -c:a aac -b:a 96k -movflags +faststart \
  out.m4a
```

### 4.3.2 严格两遍 loudnorm（推荐，成品更稳）

> ⚠️ **对 0.2–0.45 s 的卡片素材**：第一遍测量必须**先循环补足**，否则 `input_i` 会是 `-inf`，`loudnorm` 直接报错退出（`Value -inf for parameter 'measured_I' out of range`）。
> 即：第一遍用 `-stream_loop 30 -t 4`，第二遍仍作用在**原始**文件上。
> 但要注意 §4.2b 的超调警告：这种"循环测量 + 回填原片"对超短素材会偏，**归一后务必用 RMS 实测复核**。

```bash
# 第一遍：只测量（短素材需循环补足，否则 input_i = -inf）
ffmpeg -hide_banner -nostats -stream_loop 30 -i raw.wav -t 4 \
  -af loudnorm=I=-16:TP=-1.0:LRA=11:print_format=json -f null - 2>&1 | \
  sed -n '/^{/,/^}/p'

# 第二遍：把第一遍测得的 input_i / input_tp / input_lra / input_thresh / target_offset
# 原样回填（下面数值只是示例，必须换成第一遍的真实输出）
ffmpeg -hide_banner -y -i raw.wav \
  -af "loudnorm=I=-16:TP=-1.0:LRA=11:\
measured_I=-18.3:measured_TP=-2.1:measured_LRA=4.2:\
measured_thresh=-28.7:offset=0.4:linear=true:print_format=summary" \
  -ar 48000 -ac 1 -c:a pcm_s24le normalized.wav

ffmpeg -hide_banner -y -i normalized.wav \
  -c:a aac -b:a 96k -ar 48000 -movflags +faststart out.m4a
```

## 4.4 声学拼接（把切好的音素拼成音节）的注意事项

如果采用"录母音/介母 + 拼成整音节"的省力做法，必须注意：

1. **辅音段不能拼长**。塞音（b p d t g k）闭塞段 **5–15 ms** 即可；擦音（f s sh x h）**80–120 ms**；塞擦音（z c zh ch j q）**闭塞 5–10 ms + 擦段 60–100 ms**。把擦音拖到 300 ms 会变成"咝咝"，孩子听不出音位。
2. **响度对齐**：拼接前把每个片段归一到相同 RMS（统一 `-af loudnorm` 或手动 ×k），否则接缝处会有台阶，频谱上表现为"两个音节"。
3. **基频连续性**：元音片段之间若基频差 > 30 Hz，会听出跳变。用 Praat 的 `Pitch tier` 做基频插值，或在同一次录音里用连贯语调录好母音再切。
4. **共振峰连续性**：这是比基频更关键的一条——从 [i] 滑到 [u] 必须有 F1/F2 的连续过渡，硬拼会出现"两个元音"感。**结论：合成整音节优于拼接。**
5. **相位/淡入淡出**：拼接处加 3–5 ms 的等功率交叉淡化，避免咔哒声；但不要超过 10 ms，否则辅音段被削短。
6. **最稳妥的做法**：**整条音节一次性录出来**，不拼。

## 4.5 若采用拼接，Praat 的具体操作

```
# 用 Praat 提取基频并做插值（parselmouth / Praat 脚本）
# 1) 对母音段提取 pitch tier
# 2) 用 Pitch_tierInterpolate 把两个 tier 在连接点对齐
# 3) 拼接后用 Sound_extractPart 修剪掉多余静音
```
Python（praat-parselmouth）版本：
```python

# 两个 tier 之间用 parselmouth.pitch_and_intensity... 或手工做线性插值后合并
```

**取舍**：音色机械（4 岁孩子可能不接受）；**平翘舌不分是教学硬伤**。
**唯一不可替代的价值**：它是**唯一能离线产出标准第一声 fō dē tē nē lē rī 且音素全对**的免费方案（`fo1`→fˈo5、`de1`→tˈə5、`ri1`→ʐˈi.5）。
**推荐用法**：**只拿它做路线 A 里那 6 个特殊音 + 5 个声调音频**，其余 52 条仍走 Tingting 汉字 → 得到"音色统一 + 特殊音正确"的最优解。
**验收**：用 3.2 测四声；用 `--ipa` 输出人工核对音素表。

## 5.3 路线 C（真人录音 34 条）—— **质量最高，成本最高**

**范围**：34 条 = 21 个声母呼读音（bō pō mō fō dē tē nē lē gē kē hē jī qī xī zhī chī shī rī zī cī sī）+ 6 个单韵母（a o e i u ü）+ 特殊韵母 er + y/w 的本音（yī wū）。

**不录音的部分**：复韵母 8、鼻韵母 9、整体认读音节 16 → 用**路线 A 的汉字合成**，或直接录音（如果家长普通话好，录音也很快）。

**录制规范**：见 4.1–4.3。

**取舍**

| 优势 | 劣势 |
| --- | --- |
| 音素 100% 正确可控（老师能直接纠音） | 依赖成人普通话水平；r 的卷舌、ü 的撮口呼最考验人 |
| 音质最好、最适合 4 岁 | 34 条要录 34 遍 + 后期，工作量大 |
| 无引擎/版本依赖，文件固化即永久可用 | 若要补录，整体认读音节 16 条也得上 |
| 可与现成资源组合：GitHub 真人录音的**声母 21 + 整体认读 16** 可直接替换（§2.6） | 韵母只有 20/24 可用，`o`/`un`/`ong`/`eng`/`ui`/`iu`/`ie` 必须自己录或合成 |

**验收**：3.2 + 3.3 + 响度检查 + **必须由普通话母语者试听确认**，且**必须逐条与 A 路线做 mel 距离交叉比对**，防止两条路线的音互相矛盾。

## 5.4 最终建议

> **采用 A 为主 + D 补翘舌度 + C 为可选升级：**
> 1. **主方案 A（已落地并回归通过）**：58 个音用 Tingting 第一声汉字，6 个特殊音用 Tingting 简单 IPA；已修掉"7 对音频字节相同"的硬伤（实测 18/18 组真实教学对立全部通过）。
> 2. **r 的定性（已修正）**：r 的**音位本来就是对的**（起音段 d=0.839，§2.1.3b）；旧版问题在**调值**（用「日」兜底成了四声），修正版已解决。若还想把翘舌度补满，优先用 GitHub 真人录音的 `ri1.mp3`（§2.6，**21 个声母呼读音全覆盖**），其次 espeak-ng `ri1`（ʐˈi.5）。
> 3. **B（espeak-ng）只作补位**：可用于 `fō dē tē nē lē rī` 与四个声调音频；**不可作全量**（平翘舌不分）。
> 4. **C 作为长期升级**：若家长愿意投入，用真人录音替换核心音，合成保留复韵母/鼻韵母。
> 5. **无论走哪条，都必须把 §3.1–§3.4 的验收脚本接进构建流程**——本项目最大的教训是"语音生成成功 ≠ 语音正确"，而"字节去重 + mel 对立距离"这两道闸成本几乎为零，却能挡住 100% 的已发生错误。
