# 识字卡 HTML 的微信传播：深度调研与落地方案

日期：2026-10-27 ｜ 实验对象：`汉语启蒙_象形字卡.html`（副本）｜ 原件未改动（哈希核对一致）

---

## 0. 结论速览（TL;DR）

1. **微信打不开 HTML 文件是产品机制问题，不是文件坏了**：微信的「文件预览」和「内置浏览器」是两套系统，`.html` 不在文件预览的白名单里（PDF/Office/图片可以预览），加上 Android WebView 对本地 `file://` 页面有系统级安全限制、HTML 能跑脚本有钓鱼风险，所以安卓基本打不开、iOS 时好时坏（白屏/显示源码）。
2. **正确思路是「文件 → 链接」**：把单文件 HTML 部署成网址，微信里点链接直接用内置浏览器打开——体验与原生 H5 一致，还能通过右上角「···」转浏览器、收藏、加浮窗。
3. **平台选型（实测）**：Vercel 双重死（被墙+微信拉黑传闻）、Cloudflare Pages 慢且有风险、Gitee Pages 已停服、OSS/COS 默认域名会强制下载；**GitHub Pages 可用且已实测部署成功**（gzip 后 1.7MB 大卡只传 471KB，约 1.6~4 秒）；**腾讯 EdgeOne Pages 是长期主力推荐**（免费、免备案、大陆 CDN 快、腾讯系域名被微信拦风险最低）。
4. **已完成的落地**：卡片已部署上线 GitHub Pages，微信拦截检测为「安全网站」，微信 UA 下渲染验证通过；还加了仅微信内显示的「收藏/浮窗」引导条。
5. **分享动作**：群里直接发链接（或贴二维码图片），点开即用，老人小孩零门槛。

## 1. 限制的原因（机制层调研）

### 1.1 「文件预览」≠「内置浏览器」

微信里点开**链接**走的是内置浏览器（iOS 用系统 WKWebView，安卓用腾讯自研 XWeb 内核，2020 年 5 月起从 X5 切换）；点开**聊天文件**走的是微信自带的文件查看器。这套查看器只支持白名单格式（PDF、doc/xls/ppt、图片、压缩包等，与小程序 `wx.openDocument` 的支持列表同源），`.html` 不在其中（[微信文件能力/掘金](https://juejin.cn/post/6888111015280508935)、[微信小程序 openDocument 文档](https://developers.weixin.qq.com/miniprogram/dev/api/file/wx.openDocument.html)）。

### 1.2 各端实际行为

| 端 | 行为 | 来源 |
| --- | --- | --- |
| Android 微信 | 点开不渲染：白屏 / 无反应 / 提示不支持 / 显示源码，需「用其他应用打开」借浏览器看 | [kd.cn 2025](https://www.kd.cn/ask/22703.html)、[微信开放社区 2023](https://developers.weixin.qq.com/community/minihome/doc/0008a420e888d8b7ce740299466c00) |
| iOS 微信 | 不稳定：有报告称 iOS 可正常显示、安卓白屏；也有 iOS「一发微信就打不开」的实测（2026-07），无官方口径 | 同上、[知乎 OneMarkup 实测 2026](https://zhuanlan.zhihu.com/p/2065755501833589386) |
| 电脑版微信 | 调用系统默认关联程序打开（默认浏览器），基本没问题 | [jackxiang](https://jackxiang.com/post/7866) |

### 1.3 为什么这样设计

- **安全**：HTML 可内嵌 JS 伪造登录/支付页，是「钓鱼文件」的常见载体；微信对高风险文件类型一贯谨慎（apk 自动改后缀 `.apk.1` 等）（[掘金：无法被拦截的 PDF/HTML 钓鱼](https://juejin.cn/post/7469596830725259279)、[V2EX 2020](https://v2ex.com/t/682310)）。
- **系统层限制**：Android 10 起 WebView 默认 `setAllowFileAccess(false)`，禁止 `file://` 加载本地文件——聊天缓存的本地 html 即使想渲染也受限（[掘金 WebView 安全](https://juejin.cn/post/6844904151256678408)）。
- **产品定位**：微信是 IM 不是文件管理器，没动力为 HTML 做预览（[kd.cn](https://www.kd.cn/ask/22703.html)）。

### 1.4 「分享到浏览器」到底支不支持

核实结论：**对「网页」一直支持，对「文件」没有直接入口**。

- 网页（URL）：右上角「···」→「在默认浏览器中打开」（iOS 为「在 Safari 中打开」），多来源确认（[appy.to](https://appy.to/zh/tools/in-app-browser-checker)）。
- 文件：只能「用其他应用打开」（安卓可选浏览器）或先「另存」再开；iOS 上 Safari 通常不在 .html 的「打开方式」列表里，要先存到「文件」App 再用 Safari 打开，对老人基本不可行（[PingCode](https://docs.pingcode.com/baike/3156034)）。

> 所以用户的判断是对的：指望接收方「把文件弄到浏览器里打开」不现实。**必须让内容以「网页」而非「文件」的形态进入微信。**

## 2. 解决思路全景与优劣对比

| 思路 | 接收方体验 | 交互保留 | 成本/维护 | 评价 |
| --- | --- | --- | --- | --- |
| **A. 在线托管成链接**（本次主推） | 点链接即用，零门槛 | ✅ 完整（翻卡/笔顺/开关全在） | 一次性部署；改卡后 push 即更新 | **最优**。与微信 H5 生态完全兼容，可收藏/浮窗/转浏览器 |
| B. 引导「用其他应用打开」 | 差：安卓要选应用，iOS 要另存→文件App→Safari | ✅ 完整 | 零 | 仅救急；老人不适用 |
| C. 转成 PDF / 长图 | 好：微信原生预览图片/PDF | ❌ 丢失全部交互（翻卡、藏图、笔顺动画） | 每版重新导出 | 适合做「静态预告图」配合 A 用，不能当主体 |
| D. 公众号文章 | 好（微信原生） | ❌ 同上，且需要公众号、排版受限 | 高 | 不适合工具型卡片 |
| E. 小程序 | 最好（可添加到桌面） | ✅ | 很高：开发+审核+域名备案要求 | 过度工程，现阶段不值 |
| F. 网盘中转（夸克/百度盘链接） | 差：要跳 App、可能限速 | ✅（下载后本地打开） | 低 | 与 B 同病，更绕 |

结论：只有 A 同时满足「点开即用 + 保留全部交互 + 对老人零门槛」，其余思路可作为 A 的补充（如 C 用于群里「预告图」）。

## 3. 托管平台选型（社区调研 + 本机实测）

### 3.1 社区结论（2024–2026 来源）

| 平台 | 微信内表现 | 大陆直连 | 状态 |
| --- | --- | --- | --- |
| Vercel `*.vercel.app` | 传闻整段拉黑；即使不拦也打不开 | ❌ DNS 污染 | 弃用（[CSDN 2024](https://blog.csdn.net/zll_0405/article/details/136427301)、[V2EX](https://cn.v2ex.com/t/1009761)） |
| Cloudflare Pages `*.pages.dev` | 常见「无法确认安全性」警告页 | 时通时断、慢 | 不宜发家人群（[微信开放社区 2025](https://developers.weixin.qq.com/community/minihome/doc/000aec58000b10a5d473401f161800)） |
| Netlify `*.netlify.app` | 有被拦案例 | 不稳 | 弃用（[申诉帖](https://fuwu.weixin.qq.com/community/minihome/doc/00066aab2a09e8fd5b0ce4fc65b800)） |
| Gitee Pages | — | — | **2024-05 已停服**（[官方 issue I9LOM3](https://gitee.com/oschina/git-osc/issues/I9LOM3)、[知乎](https://www.zhihu.com/question/655233802)） |
| OSS/COS 静态网站 | 默认域名访问网页会**强制下载** | 快 | 需绑自定义域名（内地要备案），不适合零成本（[阿里云文档](https://developer.alibaba.com/docs/doc.htm?source=search&treeId=620&articleId=115768&docType=1)） |
| **GitHub Pages `*.github.io`** | 一般能打开，偶见「非微信官方网页」确认页（点继续即可） | 可达但速度波动 | **可用，已实测**（[CSDN](https://blog.csdn.net/weixin_45536587/article/details/105054909)） |
| **腾讯 EdgeOne Pages `*.edgeone.app`** | 腾讯自家 CDN 域名，拦截风险理论最低 | **快**（大陆有节点） | **长期主推**（[实测 2025](https://iui.su/3296)、[腾讯云](https://cloud.tencent.com/developer/article/2678691)） |

EdgeOne Pages 要点：免费（项目总量 5G 内）、国际版邮箱+GitHub 即可注册（免手机号/信用卡）、默认域名**免备案**、大陆速度优于所有海外平台；官方教程提示默认部署域名「访问可能受限时建议绑自定义域名」（国际版走海外节点但大陆可流畅访问）。产品已更名 EdgeOne Makers（[官方文档](https://cloud.tencent.com/document/product/1552/127366)）。

### 3.2 本机实测（2026-10-27 晚，本机在大陆、curl 直连不走代理）

| 目标 | 结果 |
| --- | --- |
| `vercel.app` 测试站 | ❌ 连接超时（6s 无 IP）——网络层死，与调研一致 |
| `github.io`（IPv4 185.199.x） | ✅ 可达；首页 1.0s / 象形字卡 1.2s |
| 1.7MB 大卡裸下载 | ⚠️ 18~36s（49~96 KB/s）——**但这是假象，见下** |
| 1.7MB 大卡 **gzip** 传输 | ✅ 实传 **471KB，1.6~4.1s**（GitHub Pages 自动 gzip；手机浏览器默认带 Accept-Encoding） |
| `edgeone.ai`（腾讯 EdgeOne） | ✅ 0.32s，大陆节点 IP |

### 3.3 微信拦截机制与检测

- 拦截由**腾讯网址安全中心自动检测 + 用户投诉**双触发，提示「已停止访问该网页」；正常教育内容的新域名默认不会被动碰（[微信外链规范](https://www.stonepoll.com/helpcenter/hc/kb/article/153621)、[拨测说明](https://www.boce.com/help/1418.html)）。
- 「非微信官方网页」绿色确认页≠拦截，点「继续访问」即可，常见于 github.io 这类未认证域名。
- **不用微信也能检测**：爱站微信拦截检测（tools.aizhan.com/intercept/wx）、拨测 boce.com/wechat 等。本次用爱站实测：`coderdreamworld.github.io` = **安全网站**；`edgeone.app` / `pages.dev` / `vercel.app` 父域均「安全网站」（说明黑名单粒度在子域名/投诉级；vercel 的真正死因在网络层）。第三方工具仅供参考，最终以真机微信为准。

## 4. 最终方案与已完成落地

### 4.1 架构

```
本目录源卡（不动）
   └─ 复制到 发布/github-pages/（加 favicon、微信引导条）
        └─ git push → GitHub Pages 自动发布 → https://coderdreamworld.github.io/hanzi-cards/
             ├─ index.html       导航首页（孩子的识字卡）

（推荐升级路径：EdgeOne Pages 导入同一 GitHub 仓库 → 自动部署 → *.edgeone.app，大陆更快）
```

- 二维码：本目录 `分享二维码_识字卡.png`（扫码/长按识别均可进，指向导航首页）

### 4.3 页面侧微信适配（只在副本上做）

1. **favicon（SVG data-URI）+ 规范标题**：决定微信里链接卡片的标题与图标显示。
2. **仅微信内显示的引导条**：UA 含 `MicroMessenger` 才注入，提示「点右上角···可收藏或加浮窗，下次秒开」，可关闭、sessionStorage 记忆；普通浏览器完全不出现（已用双 UA 渲染验证：微信 1 个元素 / Safari 0 个）。
3. **单文件零外链**：无外部字体/CDN/音频，微信 WebView 无资源加载风险（系统字体栈 + 内联 SVG）。
4. 原有移动端适配（`100svh`、`touchend`）本就已具备，无需改动。

### 4.4 EdgeOne Pages 升级路径（约 5 分钟，建议做）

1. 打开 <https://console.tencent.com/edgeone/pages>（或 edgeone.cloud.tencent.com/pages），用邮箱/GitHub/微信登录（国际版免手机号）。
2. 「创建项目 → 导入 Git 仓库」选 `coderdreamworld/hanzi-cards`，框架选「无/静态」，目录 `/`，部署。
3. 得到 `https://xxx.edgeone.app` 域名，把新链接发群里即可；此后每次 `git push` 自动更新线上。
4. 发群前可用爱站/拨测再查一次新域名；如默认域名偶发受限，再考虑绑自定义域名（需备案）。

### 4.5 分享操作建议

- **群里**：直接发链接（微信会显示标题卡片）；配合一张卡片截图/二维码图片更有吸引力（见 `分享文案.md`）。
- **一对一/老人**：发二维码图片，教一次「长按→识别二维码」。
- 期望系统浏览器打开：微信内打开页面后「···」→「在默认浏览器中打开」。

## 5. 自主核对与验证记录（全程未用微信）

| 层 | 手段 | 结果 |
| --- | --- | --- |
| 原件保护 | sha256 对比原件 vs 备份 | 一致 ✓（未动任何原始文件） |
| 网络层 | curl 直连（绕开本机代理）多轮采样 | vercel 死 / github.io 可达 / gzip 471KB 1.6~4.1s / edgeone 0.32s |
| 部署层 | gh 创建仓库→push→Pages API 开启→轮询 built | 三个页面全部 200 |
| 微信拦截层 | 爱站微信检测（浏览器自动化操作） | `coderdreamworld.github.io` = 安全网站 |
| 渲染层 | headless Chrome + MicroMessenger UA，500×900 手机窗口 | DOM 完整（81KB，关键标记全命中）、截图存档于 `验证截图/` |
| 适配正确性 | 双 UA 对比：微信 UA 下六套卡引导条文本均出现「源码+元素」两处（元素即已注入显示），Mac UA 仅 1 处（只有源码、不注入） | 六套全部 ✓（本地+线上一致） |
| 稳定性(更新链路) | 当晚 4 次 `git push` 有 2 次直连失败（github.com 443 超时/空回复），走本机系统代理 `127.0.0.1:15236` 后成功 | 大陆更新 github 仓库也会受波动影响，再次印证 EdgeOne 主力的必要性 |

> 排障记录（如实留档）：情绪卡曾用精确字符串 `grep '<div class="wx-tip"'` 判定为「线上未注入」，经逐行埋点 + MutationObserver 三轮定位后确认**页面实际完全正常**——http 下 `requestAnimationFrame` 在 dump 前把 class 改成了 `wx-tip show`，精确匹配因此落空；file:// 下 rAF 未执行才恰好匹配。教训：DOM 断言要用内容文本或宽松前缀，不能拿会被 JS 动态改写的属性做精确串匹配。

**已知局限（如实说明）**：
- 本机网络 ≠ 全国所有运营商/时段；github.io 在大陆的可达性历史上有波动。这正是推荐 EdgeOne 做主力、GitHub Pages 做保底双链接的原因。
- 爱站等第三方检测为参考值；首次发大群前，建议用户自己微信里点一次链接做终验（30 秒），这也是唯一无法被 Agent 替代的一步（用户微信已禁自动化，符合约束）。
- 极端兜底：若链接整体不可用，退回思路 C（导长图/PDF 群发预览 + 链接补交互）。
