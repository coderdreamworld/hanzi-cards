# 1000 字卡集 · 图片核对规则（2026-10-31 全量复核用）

本规则由 422 字项目两轮全量审计 + 用户逐卡验收的全部教训提炼而来（来源：识字卡片_审卡标准.md、识字卡片_审美教研报告.md、项目记忆中的 30+ 条逐卡修复记录）。审图 Agent 必须全文读完再开始看图。

## 范围（先读这条）

- **只审 562 张新增卡**：新模块 `素材/素材1000_*.py` 声明的卡。
- **402 张 legacy 卡（与 422 版完全相同的那批）用户已亲自核对过，明确不在本次范围**——看图时它们只是"邻居参照"，不审、不报、**更不许改**。
- 审的是渲染出来的画面。pinyin 调号、文案通顺度不重审，但**画面与例句是否一致**要审（A7）。

## 金标准

**遮住字牌，让一个 4 岁孩子看图 1 秒——他能说出画面是什么，并联想到这个字的意思吗？**
说不出来、说错、把主角认成别的东西，就是不合格。

## A 类 · 硬性禁止（违反即记，S3 必修）

| 编号 | 禁止项 | 说明（历史教训） |
| --- | --- | --- |
| A1 | **手搓人物** | 人物必须由成熟组件（lib.kid 等）构图。自绘简化小人、自制头发路径压眼、自绘人脸缺五官（尤其缺嘴）、脸画偏悬空，全部禁止 |
| A2 | **多手/多臂/断手** | 同一人身上 3 条及以上手臂；不接手臂的悬空手（画外断臂、贴纸手）；在原生双臂上再叠画自绘臂线。臂端加手圆导致"四只手"观感同罪 |
| A3 | **长臂/怪臂** | 手臂长度明显超过身高一半；连接物（绳、带、肉条）从躯干中部长出、两端不落在手上；"第二双手"从身体侧面另起 |
| A4 | **悬空物** | 球、杯子、香蕉、水龙头、支架板等无支撑悬浮（脱手、脱墙）；违反重力的构图 |
| A5 | **穿模** | 长杆/工具/伞柄的延长线穿过躯干；手臂穿腿、家具与身体互相穿插、领口/帽子盖住嘴 |
| A6 | **关节疙瘩** | 拼接手臂接缝处残留手圆/端头，手臂"中间多出来一截" |
| A7 | **图文不符** | 画面内容与例句对不上：例句提到的东西图中没有；画面讲的是另一个动作/场景；画的是 A 句子却是 B |
| A8 | **出画** | 插画元素压到字牌、底部例句条或卡片边框；元素被画布边缘裁掉一半 |
| A9 | **方向颠倒**（对比卡） | 左右两半与字牌两个字的左右顺序不一致；大小/高低/胖瘦/长短等相对关系画反；字标没压在对应半边上方 |
| A10 | **恐怖形象** | 尖牙獠牙、纯黑无脸头、三只眼、血迹、惊悚表情 |

## B 类 · 一眼即明（S2 应修）

| 编号 | 问题 | 说明 |
| --- | --- | --- |
| B1 | 认不出 | 遮字看图，说不出画面是什么 |
| B2 | 认错 | 把主角认成别的东西（狼读成狗、伞读成蘑菇这类） |
| B3 | 身份不明 | 称谓/职业卡只靠衣服颜色或发型区分，没有标志道具或互动（医生=白大褂+听诊器，爷爷=白胡子+拐杖） |
| B4 | 同组撞车 | 同组两张新卡主体轮廓+主色高度雷同会被认混；新卡与相邻 legacy 卡设计雷同同样要报 |
| B5 | 图不达意 | 虚词/抽象字卡：画面与字的用法没有语义链，是"为图造句、字不在环路里"的产物 |
| B6 | 主角不主导 | 主角占画面不足一半，抢戏的配角或装饰喧宾夺主 |

## C 类 · 质感与规范（S1 可改）

| 编号 | 问题 | 说明 |
| --- | --- | --- |
| C1 | 风格漂移 | 粗黑描边、写实阴影、明显脱离本套色板的怪色 |
| C2 | 多余装饰 | 成人符号当主表达（绿勾、绿色箭头、图表式对勾）；声波弧/速度线渲染成怪东西。约定符号（问号、红叉禁止符、爱心、淡黄高光圈）不算此列 |
| C3 | 构图瑕疵 | 人物/直立物没有地面参照（悬空站）；重心明显不稳 |
| C4 | 物理小违例 | 植物穗/果双着生点或穗轴闭环；动物尾巴搭在头上、尾巴朝头侧甩；配角比主角还大等比例失调 |

## 判定为"不是问题"（防误报清单）

- 星星、月亮、速度线、虚线轨迹、雨点等辅助符号本身（只有渲染成怪东西才算）。
- 对比卡左右分半、字标压各自半边上方——这是设计意图。
- 扁平、无描边、平涂配色——这是本套画风，不是缺陷。
- 抽象字卡使用约定符号（问号、红叉、爱心、高光圈）。
- 动作卡使用 kid() 人物是正当的；只有"自绘/改造人物结构"才违规。
- 物理指控拿不准的标"疑似"，由主控复核后才执行，不要当结论。

## 严重度

- **S3 = A 类**，必修；**S2 = B 类**，应修；**S1 = C 类**，可改。

## 汇报格式（审图 Agent）

每条问题一行：`组 | 字 | 位置 | 规则编号 | 严重度 | 现状一句话 | 建议画法一句话`；
最后按组报 PASS 数。只报分内的新增卡，legacy 卡一律不报。

## 整改纪律（修图 Agent 必读，用户明确要求）

1. **只改新模块** `识字卡片_1000字/素材/素材1000_*.py`；上级目录 422 素材文件与 legacy 卡一律只读。
2. 只修清单上点名的卡；顺手发现清单外的问题**只记录不上手**（等下一轮点名）。
3. 改前先看清卡片所在模块与函数；同一模块多卡修改合并为一个覆盖块/一次编辑，不做碎片化反复替换。
4. 改完跑该模块自检 + 重新渲染逐张目检，确认改的是点名卡本身。
5. 全部修完后主控执行：重新构建 → 与改前渲染逐卡对比，**证明除清单卡外逐卡零变化**（用户的红线：不许"改一点坏一片"）。
