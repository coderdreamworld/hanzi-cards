## 一、总判决

395 张实审：**无缺陷约 315 张（80%），带缺陷 39 张（10%），另有 41 张被评审点名"好"（真正有标杆价值的约 25 张）**。缺陷分布极不均匀——实词卡（动物/物品/植物/天文）合格率 90%+，**抽象虚词卡（常用组 25 张里 7 张不合格）和课标补充组的虚词卡（东西南北边/以/参/加/子/真/什/处/办/旁/法/许/久/点/巴）是重灾区，不合格率超过 30%**。

说难听点：这套卡的物部分是合格的，**词的部分是不合格的**。孩子翻到"猫""伞""闪电"不会有问题，翻到"就""法""旁"会完全不知道图在说什么。

## 四、根因分析——这些问题是怎么被生产出来的

1. **规范全是形容词，没有几何。** 设计规范写"友好圆润、主体突出、重心居中"，没有一条是数字。设计 Agent 每次自由发挥：妈卡的臂想多长就多长。对比卡组为什么好？因为它的规范是死 的（同一物件、只变一个维度、两半各对齐字位）——**约束越死，产出越好，这是本套管线最重要的一条经验**。
2. **组件库 API 与实现漂移，直接制造断手。** `kid(item=…)` 参数有签名无实现（手持物文档承诺了、函数体根本没接）；`hand()` 是不带手臂的独立部件。设计 Agent 要画"别"的阻止手势时，只能把 hand() 当贴纸浮在半空——**别/可/许三张是同一个 bug 的三次发病**。`cup()` 杯身无 fill 是同类问题（已绕过）。
3. **虚词没有符号表，每个 Agent 现场发明隐喻。** 名词有现实原型，虚词没有。"就"该画什么？每个设计 Agent 自己猜，猜出来的全是"够球""递花"这类动作场景——孩子读到的是动词，不是虚词。缺一张**虚词→约定视觉符号**的映射表，这一张表的缺失直接贡献了 14 张语义失败卡。
4. **同组撞车零检测。** 什/问、处/住、巴/尾、足/脚互相抄近道，因为没有任何程序或流程对比"同组卡之间的相似度"。规范第 8 条（区分度）从写入那天起就没被执行过一次。
5. **补丁式修复没有回归。** 上一轮修"妈=抱婴儿"大概改了手臂去够篮子，制造了更长的新臂；爷卡在历次修改中丢了白胡子。每次 patch 只看被改的那张卡，不看改完之后是否违反别的规则——**修复在制造新的缺陷**。
6. **构建关卡是瞎的。** `识字卡片_构建.py` 只校验字覆盖和 SVG 语法合法性，画面质量零校验。物理违例、撞车、风格漂移全部畅通无阻地进入成品。视觉审查第二轮才引入且靠人喊，不是流水线关卡。
7. **多 Agent 并行的风格漂移没有锚。** 参卡的灰白地面、窗卡的金鱼、牛卡的猪鼻——每个组 Agent 在自己文件里的小发明，没有一处被对照全局色板和组件白名单检查。

## 五、可执行优化规范（交给下一个 AI 直接照做）

### 5.1 比例常数（写进 `识字卡片_设计规范.md`，替换所有形容词）

- kid() 头身比 1:2.2–2.6；手臂总长（肩到指尖）≤ 0.55×身高；前臂 ≤ 0.28×身高
- 手必须长在臂端：**禁止独立实例化 `hand()`**——手持物一律走 `kid(item=…)`，先补齐素材库中 item 的实现（在手坐标之后画，随 arm 旋转）
- 主体包围盒中心偏移画布中心 ≤ 15%；主体高度占画布 45%–75%
- 地面椭圆只允许 `ground()`（青绿 #c8e6d8），禁止自造灰白地面
- 同组任意两卡的 SVG 结构相似度不得高于阈值（见 5.3 第 4 条）

### 5.2 虚词符号表（先建表再重画，缺这张表谁画谁崩）

| 字 | 标准视觉方案（双人物最小对优先） |
| --- | --- |
| 就 | 最小对才：同一场景两卡——球放在手边（伸手就拿到）vs 球在柜顶（踩凳才拿到）；"就"卡必须有"近/易"视觉线索（虚线短） |
| 才 | 同上，"远/难"线索（虚线长+汗滴） |
| 的 | 尾巴明确的狗 + 高亮圈住尾巴：狗**的**尾巴（所属物+归属高亮） |
| 了 | 分两格：满碗→空碗+擦嘴（完成态对比） |
| 在 | 小人在椅子**上**+黄色高亮圈住"椅子+人"的整体（位置高亮，不是只画坐） |
| 再 | 同一动作两格：第一次挥手→第二次挥手（两格重复=再一次） |
| 每 | 三个相同的球每个头上都有勾（逐个指示，不是只圈一个） |
| 别 | 大人手按住小孩伸向插座的手（阻止必须身体接触，断手禁止） |
| 法/办/旁/久/点/以/参/加/边 | 按 5.2 的思路逐字建最小对场景后才允许动笔；建不出约定俗成方案的，降级为"家长读句+中性场景图"（画字句里的实词，如"法"画"想办法"的完整小故事） |

### 5.3 构建期自动校验（写进 `识字卡片_构建.py`，不合格拒绝出 HTML）

1. **连通域计数**：ElementTree 解析每卡 SVG，统计 SKIN 色 (#f8cba4/#eeb28a) 独立形状数——kid 正常为 头2臂2腿 等，出现孤立 skin 形状且不与任何臂 transform 组相邻=断手/断臂，报错
2. **hand() 白名单**：源码级检查——`hand(` 出现处必须位于包含 `rotate` 且起点坐标等于臂端点的 group 内，否则报错
3. **包围盒检查**：主体（非 ground 最大色块群）中心偏移 >15% 或高度 <35% 画布=报错
4. **同组撞车检测**：每卡提取「色块序列+主色+包围盒宽高比」指纹，同组两卡指纹距离低于阈值=报错（什/问、处/住、巴/尾这类会被这条全部抓住）
5. **地面颜色断言**：ground 之外出现新的灰白椭圆=报错
6. **铁律断言**：称谓卡按字典检查必备道具（爷→白胡子+眼镜+拐杖；医→白大褂+听诊器；师→黑板+教鞭），缺即报错

### 5.4 视觉 QA SOP（合并前的强制关卡）

1. `识字卡片_预览.py` 渲染全组（**修复切块行高：实测每行 ≈465px，当前脚本 590 的估算导致切块漂移**，本次审计的 9 处"裁切伪影"皆源于此）
2. 每 50 卡一个审查 Agent，按本报告第三节的四类标准输出 JSON；severity≥2 不允许合并
3. 修复 Agent 只改自己组的模块文件；**修复后必须重跑 5.3 全部校验 + 相邻卡撞车对比**，防止补丁制造新缺陷（妈卡就是前车之鉴）

### 5.5 重画优先级清单

- **P0（物理违例，5 张）**：别、可、许、妈、洗 —— 全部走"hand 接臂 + 比例常数"重画
- **P1（语义失败+撞车，20 张）**：就、法、旁、久、点、边、以、参、加、子、真、了、的、再、每、什(与问二选一重画)、处(与住)、巴(与尾)、足、爷(补白胡子)
- **P2（画质瑕疵，11 张）**：蜂、虎(与猫拉开主色)、柳、影、发、肚、杏、枫、窗、参(地面颜色)、来
- 语义类重画一律先过 5.2 符号表，没有符号表不许动笔

### 5.6 与插画试验结论的衔接（识字卡片_插画试验/试验与评审结论.md）

虚词卡按 5.2 建表后仍有两类归宿：能落成"双人物最小对"的继续用 kid() 代码画（约束死、体积小）；实在无法具象的虚词（么/着/以/为）考虑走图像模型路线的"家长句+实词场景"方案（qa 已验证单卡 18.9KB、全集 7.5MB 可承受），或干脆接受"图示辅助而非图示表义"，在卡面把家长句提到更显眼的位置。
