# 插画方案实测与评审结论（2026-10-25）

五个候选方案用同一道题「找——小孩举放大镜看瓢虫」各画一张，统一 760×480 卡面规格，由三个独立评审子 Agent 分别从**儿童视角、解剖与语义、风格协调与量产**盲评。总对照图：`render/对照_全部方案.png`（建议先看这张）。

## 评分汇总（三评审均分，10 分制）

| 方案 | 儿童视角 | 解剖语义 | 风格协调 | **均分** | 单卡体积(SVGO后) | 402卡全集 |
| --- | --- | --- | --- | --- | --- | --- |
| **E 图像模型+vtracer+SVGO** | **8.7** | **8.5** | 6.0 | **7.7** | 18.9KB（低参档11.2KB） | **7.5MB ✓** |

## 关键结论

1. **画质与贴切度：E 断层第一，且 12MB 装得下。** 评审原话："小手真实握住镜柄""六张中唯一手-柄-镜三点齐备的可信持握""瓢虫带腿和触角且明显放大"。AI 原图 177KB → vtracer 中档 43KB → SVGO 后 **18.9KB**，画质肉眼无损；402 张全集约 7.5MB，12MB 红线内还有余量（低参档 11.2KB 可再压到 4.4MB）。
2. **现状卡的问题被评审精确复现**：解剖评审确认 REF"手臂过长、腿短到接近消失、放大镜根本没被拿住、镜内物体无法识别"，均分 4.0 低于所有代码方案。
3. **A（组件用对）证明不换技术栈也能及格**：用 kid() 正确姿势+补上缺失的持物逻辑，均分反超现状 2 分。素材库 `item` 参数只有签名没有实现，是现库的真实缺口。
4. **部件库（B/C）做人物主力不行**：Open Peeps 是成人比例（"孩子难以代入小朋友在找"），Humaaans 无五官脸+冷色时尚风与低幼绘本冲突。但 B 的抓握可信度是代码路线最高，可作 AI 翻车时的替换素材。
5. **DiceBear 彻底退出动作场景**（均分 2.7）：头像无身体无动作，"举镜观察"链条一环都不存在。但其 adventurer 等儿童风适合**名词卡**（动物/物品/人称），确定性生成 3-11KB。
6. **E 的唯一真实风险=量产一致性**（风格评审给一致性潜力打 4 分）：单张无法证明 400 张锁得住同一角色。生产时必须配：角色圣经 prompt 模板 + 参考图/LoRA 式风格锚定 + 每卡视觉 QA 子代理 + 翻车重生成；另有三个已定位的小修：眼神要看向镜片（prompt 补"眼睛看向放大镜"）、出图裁掉上下白边、放大镜圈色锁成铜木色。

## 落地建议（按优先级）

1. **主力路线换成 E**：qwen wanx（本机 dashscope key 可用）逐卡生成 → vtracer(mid 档) → SVGO → 内联。生成 prompt 从角色圣经模板出，QA 用本轮已验证的子代理视觉评审法，不通过重roll。
2. **名词卡走 DiceBear**（adventurer/big-smile 等儿童系风格），动词/场景卡走 E。
3. **保留并改良组件库路线**做兜底（抽象字、几何概念卡最适合代码画）：落地比例常数表 + SVG 几何校验脚本 + 补 kid() 的 item 手持物实现。
4. B/C 部件库仅作素材备胎，不再投入。

## 试验中踩的坑（复用时注意）

- Open Peeps 官方仓库已 404，可用的替代是 npm 包 `@opeepsfun/open-peeps`（React 组件，需 react-dom 服务端渲染），且**包缺 `fill-rule: evenodd`**，渲染要在 SVG 根节点补 style，否则人物糊成剪影。
- DiceBear 各风格 viewBox 不同，且内部 `<use>` 需要 xmlns:xlink；多风格拼一张图时 def id 必须加前缀防冲突。
- vtracer 参数：flat 插画用 `filter_speckle=10, color_precision=6, layer_difference=32, path_precision=3` + SVGO `--multipass --precision 2`，体积可从 113KB 压到 19KB。
- 本机生图通道：qwen/dashscope key 可用（wanx2.1-t2i-turbo）；coze token 无图像权限（403）；智谱 key 过期（401）；火山 key 无 seedream 权限（404）。
- Chrome headless 渲染 SVG 时窗口尺寸必须匹配 SVG 固有尺寸，否则只截到左上角。
